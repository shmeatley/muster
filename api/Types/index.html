Types

Every type Muster exposes, in one place with no runtime dependencies. The aggregator re-exports all of these, so consumers should write Muster.MatchEnvelope rather than reaching in here.

Types​

Metadata​

</>
type Metadata = {[string]: any}

Arbitrary consumer data carried on a ticket. Must survive a JSON round trip through MemoryStore: strings, numbers, booleans, and tables of those. No functions, no Instances, no cycles.

Member​

</>
interface Member {
userId: number
serverId: string--

JobId of the server that enqueued them. The broadcast address.

rating: number?--

Present if and only if the queue is rated.

provisional: boolean?--

True when rating.default was substituted for a missing rating.

metadata: Metadata?
}

One player inside a ticket or a finalized match. serverId is per-member rather than per-ticket because a party can span several servers, and each member's own server is the one that needs to hear about the match.

Ticket​

</>
interface Ticket {
id: string
queue: string
partition: string
partyId: string?
leaderUserId: number
members: {Member}
size: number
rating: number?--

Party-aggregated rating, absent on unrated queues.

metadata: Metadata?
queuedAt: number
expiresAt: number
state: "Queued" | "Claimed" | "Matched" | "Cancelled"
matchId: string?
lane: number--

Index within the partition.

laneCount: number--

The lane count in force when it was written; lanes scale at runtime.

}

A queue entry. One ticket covers one solo player or one whole party — parties are never split across matches.

MatchEnvelope​

</>
interface MatchEnvelope {
v: number--

Schema version.

matchId: string
queue: string
partition: string
createdAt: number
size: number--

Total players across all members.

members: {Member}
ticketIds: {string}
partyIds: {string}
data: T--

Whatever your finalize hook returned.

}

A finalized match, delivered to every server holding one of its members. Generic over the finalizer's return type, so match.data.accessCode is typed and autocompletes.

Deduplicate on matchId, never on the set of players — see the finalize contract on Matchmaker.

MatchContext​

matchId: string

partition: string

size: number

Mean member rating, absent on unrated queues.

createdAt: number

Monotonic time the hook must return by.

}

What a finalize hook receives. Everything about the match except the decoration the hook itself is about to produce.

AbortReason​

</>
type AbortReason = "FinalizerError" | "FinalizerTimeout" | "FinalizerTooLarge" | "LeaseLost" | "StoreUnavailable" | "TicketStolen"

Why a match that had already claimed its tickets failed to commit.

  • FinalizerError — the hook threw.
  • FinalizerTimeout — the hook did not return within finalizeTimeout.
  • FinalizerTooLarge — the hook's return value failed validation or exceeded maxMatchDataBytes.
  • LeaseLost — another server took over this lane while the hook was yielding.
  • StoreUnavailable — MemoryStore rejected the final commit.
  • TicketStolen — a ticket was claimed by another match between selection and commit.

AbortContext​

</>
interface AbortContext {
matchId: string
queue: string
partition: string
members: {Member}
reason: AbortReason
message: string?--

The hook's error text, when reason is FinalizerError.

data: any?--

The hook's return value, if it produced one before the abort.

}

Passed to onAbort. When data is present the hook ran to completion and its side effects survived a match that never formed — that is what this callback is for.

Finalizer​

</>
type Finalizer = (context: MatchContext) → T

Runs exactly once per matchId, on whichever server formed the match, after its tickets are claimed and before it commits. Yielding is expected — this is where TeleportService:ReserveServerAsync goes.

Store​

</>
interface Store {}

The storage contract. Muster.stores.MemoryStore implements it against Roblox MemoryStore; Muster.stores.InMemory implements it in a table for tests. Every method returns (success, value) and never throws.

update must be a compare-and-set: the transform may be invoked more than once, and returning nil from it must abort the write.

Messaging​

</>
interface Messaging {}

The notification contract. Delivery is assumed best-effort and unordered — Muster never depends on a message arriving.

Candidate​

</>
interface Candidate {
ticketId: string
partyId: string?
size: number
rating: number?
ratings: {number}
queuedAt: number
}

The denormalized view of a ticket that the matcher sees. Deliberately small: it is what gets written into the lane index, and it is read far more often than the ticket itself.

MatcherPolicy​

</>
interface MatcherPolicy {
minSize: number
targetSize: number
maxSize: number
fallbackAfter: number--

Seconds before a below-target group is accepted.

compatible: (
anchor: Candidate,
candidate: Candidate,
waitSeconds: number
) → boolean
score: (
candidates: {Candidate},
indexes: {number}
) → (
number,
number
)
}

Everything the grouping algorithm knows. Supply your own to replace the rating window with role composition, region affinity, or anything else.

score returns (primary, secondary), both minimized, compared in order. The built-in policies use rating spread then total queue time.

RatingConfig​

</>
interface RatingConfig {
window: number?--

Starting rating tolerance. Default 200.

relax: number?--

Extra tolerance per second waited. Default 40.

maxWindow: number?--

Ceiling on the widened window. Default infinite.

unbounded: number?--

Seconds after which any rating matches. Default 60.

default: number?--

Substituted when a caller omits a rating. Default nil, which makes omission an error.

aggregate: (({number}) → number)?--

Party rating from member ratings. Default is a max-biased mean.

}

Presence of this table is what makes a queue rated. Omit it entirely for an unrated queue, where tickets carry no rating and matching is oldest-first.

SizeConfig​

</>
interface SizeConfig {
min: number
target: number?
max: number?
}

Match sizing. Muster.new{ size = 6 } is shorthand for all three being 6. A group at target commits immediately; a smaller one waits fallbackAfter seconds before it will settle for anything down to min.
