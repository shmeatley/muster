InMemoryStore

A complete Store backed by tables, with a synthetic clock, working TTL expiry, call counting and fault injection.

Muster's own suite runs against it, and it ships publicly so consumers can test without MemoryStore, Studio, or real time passing. 

local now = 0
local store = Muster.stores.InMemory.new(function() return now end)

local queue = Muster.new({
	name = "test", size = 2,
	store = store, clock = function() return now end,
	autoStart = false, broadcast = false,
})

queue:enqueue(1)
queue:enqueue(2)
queue:step()          -- matched, deterministically, with no yielding

now += 200            -- everything expires exactly like it would live

InMemoryStore:failNext and InMemoryStore:conflictNext inject the two failure modes worth testing against.

conflictNext​

mutator: ((any) → any)?--

Receives the current value and returns the competing writer's value. Omit to re-run against unchanged state.

) → ()

Makes the next count updates lose a compare-and-set race.

The transform runs once against the value it read, that result is discarded, mutator installs a competing write, and the transform runs again against the new value, which is what UpdateAsync does under contention.

This is what catches a transform that fails to reset its own bookkeeping when re-entered, which every conditional write in Muster depends on.
