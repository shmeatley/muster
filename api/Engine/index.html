Engine

The coordination layer. Matchmaker is the public face of this; everything interesting happens here.

How a match forms

Every server runs the same loop and is both a producer and an opportunistic worker — there is no dedicated matchmaker server to elect, provision, or lose.

  1. Enqueue. Reserve each member's userId (compare-and-set, so a player cannot hold two tickets), write the ticket, then write a small denormalized copy into the lane's sorted map keyed by queue time.
  2. Acquire. The server tries to lease the lanes its own tickets landed in. Whoever wins does the matching for that lane.
  3. Scan. Read the oldest candidates, run the pure Matcher, and commit each group it returns.
  4. Commit. A two-phase, fenced protocol — see _commit.
  5. Deliver. Publish a doorbell to the servers holding the matched players. Every one of them also polls, so delivery is guaranteed by the ledger and merely made fast by the message.

What happens when a server dies

Nothing cleans up, and nothing needs to. Every piece of state has a TTL that makes the failure self-correcting:

Failure Recovery
Worker dies holding a lease Lease expires in 15s; the next acquirer's epoch fences out any late write from the dead one
Worker dies mid-commit Claims expire; another worker repairs them, adopting the match if it committed and aborting it if it did not
Producer dies with tickets queued Heartbeats stop, tickets self-evict within ticketExpiration
Everything dies The queue drains itself and the next server starts clean
