Engine

The coordination layer behind Matchmaker.

Every server runs the same loop and acts as both producer and worker; there is no dedicated matchmaker server.

The loop

  1. Enqueue. Reserve each member's userId by compare-and-set so a player cannot hold two tickets, write the ticket, then write a denormalized copy into the lane's sorted map, keyed by queue time.
  2. Acquire. Take leases on the lanes this server's own tickets landed in. The lease holder does the matching for that lane.
  3. Scan. Read the oldest candidates and run Matcher over them.
  4. Commit. Two-phase and fenced; see _commit.
  5. Deliver. Announce the match to the servers holding its players. Those servers also poll, so delivery does not depend on the announcement.

Recovery

State is recovered by expiry rather than cleanup:

Failure Recovery
Worker dies holding a lease The lease expires after 15 s and the next holder takes it at a higher epoch, which rejects any late write from the dead one
Worker dies mid-commit Claims expire; the next worker adopts the match if it committed, and aborts it if it did not
Producer dies with tickets queued Heartbeats stop and the tickets expire within ticketExpiration
