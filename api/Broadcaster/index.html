Broadcaster

Cross-server delivery of committed matches.

MemoryStore is the source of truth; MessagingService only shortens the wait. A match is written and flipped to Ready before anything is published, so losing every message costs latency and nothing else.

Addressing

One topic per server, named <namespace><version>:<serverId>, with each instance subscribed to exactly one. A match is published only to the distinct servers holding its members, typically two to six.

A single shared topic would instead deliver every match to every server. With Roblox's per-universe receive budget of 400 + 200 x servers per minute, that caps the experience at roughly 200 matches per minute regardless of size, so per-server topics are used instead.

topicShards folds servers into a fixed number of topics if topic cardinality ever needs limiting; 0, the default, means one per server.

Payload

Envelopes under inlineBroadcastBytes (600) are sent inside the message, saving the receiver a read. Larger ones send only the matchId and the receiver reads the ledger. An inline envelope is safe to trust because it exists only after the commit succeeded.

Health

A failed publish, or a match found by polling that should have arrived as a message, marks delivery unhealthy for BROADCAST_UNHEALTHY_DURATION (300 s). While unhealthy, tickets poll on a much tighter cap.
