Lanes

Key layout for the queue index.

A queue is divided into partitions, whatever partitionKey returns or "all" by default, and each partition into lanes. A ticket lands in exactly one lane and is matched only against the other tickets in it.

What shares a lane

Lanes buy parallelism by splitting the pool, so which tickets share one decides whether the split costs anything. There are two schemes, and the queue's own configuration picks between them:

  • Bands, on a rated queue left on lanes = "auto". A lane is a contiguous rating range: lane 0 holds everyone below the first boundary, the last lane everyone above the last. Splitting a rated queue by rating separates players who would not have matched anyway, so four high-rated players queueing at once always land together.
  • Hashes, on an unrated queue or a pinned count. A ticket's lane is hash(ticketId) % count. With no rating there is nothing to order players by and every ticket may match every other, so an even spread is the best split available.

Both are deterministic: two servers holding the same layout agree on a ticket's lane without coordinating.

Generations

LaneScaler changes the layout at runtime. A band layout can change without the count changing, so a monotonic generation number, alongside the count, is stamped into every key: 

mu1:ranked:idx:EMEA:n04g7:02
                    ^^^^^ ^^
                   layout lane

The stamp is what makes changing the layout safe: servers that disagree about it read and write separate key spaces rather than one shared space, and a ticket always stays in the lane its writer chose. A descriptor's legacy covers the window where both generations hold live tickets.

Sort keys are queue timestamps, so an ascending range read returns the oldest tickets first.

laneFor​

Which lane a ticket belongs to under layout. Deterministic, so two servers using the same layout agree without coordinating.

rating is the ticket's party-aggregated rating and is only read in band mode, where it is what decides the lane. It is never absent there in practice, since a rated queue rejects a ticket without one; a missing rating falls into the lowest band.

legacyLanes​

</>
Lanes.legacyLanes(
layout: Layout,
lane: number,
previous: Layout?
) → {number}

The lanes of previous that may hold tickets belonging to lane under layout. A worker reads their maps alongside its own while the old generation drains.

  • Bands: a ticket's band follows from its rating, so the old lanes that can hold one of this lane's tickets are exactly those whose range overlaps this lane's. Layouts change by one boundary at a time, which makes that one old lane after a split and two after a merge.
  • Hashes: both counts are powers of two, since the scaler only doubles or halves, which makes this exact. A ticket hashes to h % count: growing, a ticket in old lane o satisfies h % previous == o, so reading old lane lane % previous covers it; shrinking, h % count equals (h % previous) % count, so every old lane o with o % count == lane contributes.

Either way the result holds at most previous.count / count entries.
