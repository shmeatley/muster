Matchmaker

A single queue. Construct one per game mode.

local duels = Muster.new({ name = "duels", size = 2 })

duels.matched:connect(function(match)
	for _, member in match.members do
		print(member.userId, "->", match.matchId)
	end
end)

duels:enqueue(player.UserId)

Constructing a queue starts its worker thread, subscribes it for cross-server delivery, and connects Players.PlayerRemoving to cancel tickets. Each of those can be disabled with autoStart, broadcast, and autoCancelOnLeave.

Configuration

name and size are required; everything else has a default.

Field Type Default Effect
name string — Namespaces this queue's keys. Max 16 characters, alphanumeric plus _ and -.
size number | SizeConfig — 6 is shorthand for { min = 6, target = 6, max = 6 }.
rating RatingConfig? nil Present makes the queue rated. See RatingConfig.
fallbackAfter number 10 Seconds before a below-target group is accepted.
finalize Finalizer<T>? nil Runs once per match; its return value becomes match.data.
finalizeTimeout number 5 Seconds. Must not exceed 15.
onAbort AbortHandler? nil Called when a match fails after its hook ran. Requires finalize.
partitionKey function? nil Returns a partition name per ticket. Partitions never match each other.
lanes "auto" | number "auto" Pinning a number disables runtime scaling. See LaneScaler.
broadcast boolean true Publish match notifications over MessagingService.
autoStart boolean true Start the worker thread on construction.
autoCancelOnLeave boolean true Cancel a player's ticket when they leave.
manualAcknowledge boolean false Require Matchmaker:acknowledge to release matched players.
ticketExpiration number 180 Seconds a ticket survives without a heartbeat. Minimum 30.
maxMetadataBytes number 1024 Per-ticket metadata budget.
maxMatchDataBytes number 4096 Budget for the finalizer's return value.
namespace string "mu" Change to run independent deployments in one universe.

These accept injected implementations, primarily for tests: store, messaging, players, matcher, layout, logger, metrics, clock, monotonic, random, sleep, spawn, id, serverId.

Delivery

matched fires on every server holding at least one of the matched players. A server holding none of them does not receive the event, so a handler can assume it has someone to act on.

Matches are written to MemoryStore before being announced, so delivery does not depend on MessagingService. Typical latency is under 200 ms; if a message is dropped, a poll finds the match within pollIntervalMax (30 s), and if MessagingService is unavailable the poll cap tightens to 5 s automatically.

enqueueGroup​

</>
Matchmaker.enqueueGroup(
self: any,
userIds: {number},
options: GroupOptions?
) → Result<Ticket>

Queues a set of players as one ticket. The group is never split across matches and is matched at its aggregate rating.

Takes userIds directly and does not involve Party. The first userId becomes the ticket's leader, which is who may cancel or acknowledge it. 

queue:enqueueGroup({ leaderId, friendId }, { ratings = ratings })

Groups larger than size.max are rejected with InvalidPartySize, and a repeated userId with DuplicateMember.

Queues a Party by id. Only the party's leader may call this.

The party's membership is locked for the lifetime of the ticket: invites, kicks, leaves, leadership transfers and disbanding all return PartyLocked until the ticket matches, is cancelled, or expires.

cancelForUser​

</>
Matchmaker.cancelForUser(
self: any,
userId: number
) → Result<boolean>--

True if a ticket was cancelled, false if the user had none queued.

Cancels whatever ticket a user currently holds, if any.

Unlike Matchmaker:cancel, this looks the ticket up and cancels it as its leader, so it works for any member of a group. Connected to Players.PlayerRemoving unless autoCancelOnLeave is disabled.

getMatch​

</>
Matchmaker.getMatch(
self: any,
matchId: string
) → Result<MatchEnvelope<T>?>

Reads a committed match by id, or nil if there is no ready match under that id. Matches remain readable for matchExpiration (300 s), which covers a player who rejoined on another server and needs the envelope again.

acknowledge​

</>
Matchmaker.acknowledge(
self: any,
requesterUserId: number,
ticketId: string
) → Result<MatchEnvelope<T>>

Releases a matched ticket's players so they may queue again, and unlocks its party.

This happens automatically on delivery unless manualAcknowledge is set. Enable that setting to hold the reservation until you have confirmed whatever follows the match — a teleport, for instance — so a failure leaves the players free to re-queue rather than locked out until their reservation expires.

step​

</>
Matchmaker.step(self: any) → ()

Runs one worker pass: ticket upkeep, lane acquisition, then a scan of each held lane.

The worker thread calls this on a loop. Calling it directly advances the system one step, which is how the test suite drives it without yielding.

start​

</>
Matchmaker.start(self: any) → ()

Starts the worker thread and subscribes for cross-server delivery. Called by the constructor unless autoStart is disabled. Calling it twice does nothing.

stop​

</>
Matchmaker.stop(self: any) → ()

Stops the worker and releases every lane lease this server holds, so another server can take them immediately instead of waiting out the 15-second timeout. Suitable for game:BindToClose.

destroy​

</>
Matchmaker.destroy(self: any) → ()

Calls Matchmaker:stop, disconnects the PlayerRemoving connection, and drops every signal handler.

health​

A snapshot of this server's view of the queue, for logging or a debug command.

Field Meaning

ownedLanes Lane leases this server currently holds.
laneMode "auto" or "fixed".

laneChanges Resizes this server has applied.
