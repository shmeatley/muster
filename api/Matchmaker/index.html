Matchmaker

A queue. Construct one per game mode, enqueue players, and listen for matches. 

local Muster = require(ReplicatedStorage.Packages.Muster)

local duels = Muster.new({ name = "duels", size = 2 })

duels.matched:connect(function(match)
	for _, member in match.members do
		print(member.userId, "->", match.matchId)
	end
end)

duels:enqueue(player.UserId)

That is the whole setup. The worker starts itself, subscribes for cross-server delivery, cleans up when players leave, and matches on its first scan.

The finalize hook

Muster stops at the match envelope: it never teleports and never reserves servers, because every game wants that done differently. Instead, finalize runs once per match on whichever server formed it, and whatever it returns is attached to the envelope as match.data and delivered to everyone. 

local ranked = Muster.new({
	name = "ranked",
	size = { min = 4, target = 8, max = 8 },
	rating = { window = 150, relax = 25, default = 1000 },

	finalize = function(match)
		return {
			accessCode = TeleportService:ReserveServerAsync(ARENA_PLACE),
			map = pickMap(match.size),
		}
	end,
})

ranked.matched:connect(function(match)
	local present = {}
	for _, member in match.members do
		local player = Players:GetPlayerByUserId(member.userId)
		if player then table.insert(present, player) end
	end
	if #present == 0 then return end
	TeleportService:TeleportToPrivateServer(ARENA_PLACE, match.data.accessCode, present)
end)

The contract for that hook, which is worth reading before you write one:

  • It runs exactly once per matchId, never concurrently for the same one.
  • It may run more than once for the same set of players under different matchIds, if a worker stalls and another repairs its work. Deduplicate on matchId, never on the player set.
  • Its side effects may survive a match that never forms — the lease can be lost during the yield. Write it to be idempotent or cheap to abandon, and use onAbort to release anything expensive.
  • If it throws, times out, or returns something unstorable, the match aborts cleanly and every player goes back in the queue.

Delivery

matched fires on every server holding one of the matched players, not just the one that formed the match. If none of the players are on this server, it does not fire here at all — so the handler can assume it has someone to act on.

A match is written to MemoryStore before it is announced, so delivery does not depend on MessagingService: typically it arrives in under 200 ms, and if messaging is down entirely a poll finds it within a few seconds.

</>
Matchmaker.enqueueGroup(
self: any,
userIds: {number},
options: GroupOptions?
) → any

Queues a set of players as one indivisible ticket: never split across matches, matched at the group's aggregate rating.

This is the usual way to queue a group. It needs no party system at all — pass whatever userIds you have, from your own squad code or from a party that lives in a table on this server. Reach for Party only when a party has to survive its members being on different servers. 

queue:enqueueGroup({ leaderId, friendId }, { ratings = ratings })
